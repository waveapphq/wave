# V-PLUGIN-CSV-FUNCTIONAL: CSV Parser execution

Verify the CSV Parser plugin end-to-end: PARSE typing, schema mapping + mismatch
policy, declarative sort/filter transforms, SERIALIZE, and Table query methods in
expressions.

## Prerequisites

No seed. Each test imports its own fixture via `POST /tests`, validates it (zero
errors), then runs it in the workbench. No real service - CSV content is inline.

## Fixtures

| Fixture | Cases | Covers |
|---------|-------|--------|
| `parse-typing` | P1-P17 | auto/string typing, int->float widening, bool vs 1/0, leading-zero/plus/non-finite guards, empty->None, all-empty->string, empty-default |
| `parse-schema` | S1-S3b | schema mapping by header name + by position; on_mismatch skip_row / replace_default (errors + row/column) |
| `parse-mismatch-fail` | S4 | on_mismatch=fail aborts the run |
| `transform` | T1-T8, T10-T12 | sort (single/multi-key), filter (literal, expression `_cell`, AND/OR, two blocks, index ref, workflow-var + reference-expression), sort+filter combined |
| `transform-unknown-op` | T9 | unknown filter operator aborts |
| `serialize` | Z1-Z6, Z8 | table->text with header/delimiter/None/bool/float; parse->serialize round-trip |
| `serialize-wrong-type` | Z7 | serialize a non-table aborts |
| `expr-methods` | - | `Table.filter().order_by()` chaining in the expression sandbox |

`expected.json` holds the ground-truth console lines (generated by running the real
plugin), which the spec asserts verbatim.

## Steps

1. `./scripts/e2e-targeted-local.sh functional/csv-parser/<spec>.spec.ts` from the root of
   the clone, or the whole suite via `./scripts/ci-playwright-local.sh`.

## Validation

- **Passing fixtures:** run reaches `passed`; every `expected.json` line for that
  fixture appears in the console.
- **Aborting fixtures:** run reaches `failed`; the failing node shows
  `data-execution-status="failed"`; the console carries the exact error
  (`Type mismatch in column 'age': 'abc' is not a valid integer`,
  `Unknown filter operator: 'bogus'`, `Parameter 'table' expects table, got str`).
- **Variable_ref regression:** serialize (`table`) and schema (`schema_source`) use the
  UI-faithful literal form (bare variable name, no `expressionFields`), so they regress
  the backend fix that resolves plugin `variable_ref` inputs at execution.

# V-PLUGIN-CSV-UI-TRANSFORM: sorts and filters built in the sheet

- Spec: `v-plugin-csv-ui-transform-functional.spec.ts`; fixture: none.
- Seed: blank Tests (`POST /tests`). The CSV blocks, their content, sorts, filter blocks with
  literal conditions, the Table outputs bound to new variables and a Log printing the kept ids
  are all built through the UI (`helpers/table-transform.ts`). Per "as" type one more Test holds
  one CSV block per operator and column, its filter generated in the shape the sheet stored
  (`filterMatrixSeed`).
- Validation: the CSV block ends `success` and the Log prints `c,b` (sort `amount` descending,
  filter `amount` as Integer greater than 5; CSV-12, REQ-3.4.1.12).
- Validation: per "as" type (String, Integer, Float, Boolean) a filter built in the sheet keeps
  its ids and stores exactly the generated shape; every operator of the type keeps the expected
  ids on a held column and on a column whose row b holds null, where only not equals, does not
  contain and is null keep the null row (REQ-3.1.3.25).
- Validation: sorts built in the sheet by name and by index, ascending and descending, order
  the rows; two keys keep their priority; a null cell sorts last (CSV-7).
- Validation: a filter built as String and switched to Integer stores `value_type: integer` and
  keeps amounts 8 and 12 of 3, 8, 12.
